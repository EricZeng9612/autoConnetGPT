# Remote / 任务状态采集器契约

这是**扩展接口，不是已经接入的官方 Remote 健康 API**。本仓库没有可保证正确的内置 Remote/任务采集器。默认保持 `unknown`，不会以“没有日志”“进程存在”或“端口可连”推断手机在线，也不会因缺少证据重启应用。

若你已有可信的 Remote 控制端/应用集成，可以由独立采集器原子写入下面的 JSON 文件，然后在 `config.json` 中设置 `remote_evidence_file` 和 `task_evidence_file` 的绝对路径。两份证据必须绑定 **ChatGPT 主进程**（不是 shell/守护程序/App Server 的 PID）。不要使用定时刷新时间戳的静态文件，这会掩盖真实故障。

## 字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `pid` | 整数 | 当前 ChatGPT 主进程 PID |
| `process_started_at` | Unix 秒数 | 与系统进程启动时间相差不超过 1 秒 |
| `observed_at` | Unix 秒数 | 真正采集时间，不晚于现在，不早于进程启动 |
| `status` | 字符串 | 下表规定的状态；其他值按 unknown 处理 |

以下为**格式示意，时间/PID 为虚构旧值，不能用于实际恢复**：

```json
{
  "pid": 12345,
  "process_started_at": 1700000000,
  "observed_at": 1700000010,
  "status": "unknown"
}
```

Remote 状态（有效期 120 秒）：

- `healthy`：从实际 Remote 通道获得新鲜的在线/握手/心跳成功结果。结果的覆盖范围取决于采集端；主机侧观察不保证手机端端到端成功。
- `failed`：明确的连接失败，而非日志未出现或采集器没有返回。
- `auth_required` / `pairing_required`：需人工处理，不触发重启。
- `unknown`：接口不可用、状态无法确认、故障原因不明确。

任务状态（有效期 30 秒）：`idle`、`busy`、`unknown`。只有可信地覆盖当前实例**所有正在执行任务**的 `idle` 才能授权自动重启；不能只看 UI 窗口、CPU 使用率或某一个任务。如果采集接口无法提供这一保证，应输出 `unknown`。

两次失败确认必须绑定同一主进程，观察时间递增且检查间隔 60 秒；重复读取同一条失败不算两次。进程重启后旧证据失效，必须重新采集。建议采集器每 10–15 秒更新，停止采集后证据会自动过期。

文件应置于当前用户私有目录，权限 `600`，使用同目录临时文件加原子替换，避免读到半份 JSON。程序拒绝其他用户拥有或向组/其他用户开放权限的证据文件。不要记录令牌、消息内容或用户输入。本工具不执行采集器文件中的任何命令。
